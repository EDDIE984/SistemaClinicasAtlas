1. Descripción general

El webservice /api/imagen-base64 recibe el id_cita_servicio y una imagen en base64, valida la imagen y la guarda directamente en la columna cita_servicio.foto_pedido_base64.

Casos de uso principales:

  • Servicios externos / Postman — guardar la fotografía del pedido médico asociada a una cita ya existente.
  • Dashboard de Servicios — adjuntar fotografía del pedido médico cuando ya se conoce el id_cita_servicio.
Este endpoint sí almacena la imagen. El valor guardado es un data:image/...;base64,... normalizado en la tabla cita_servicio.

3. Formato de la petición

Body (JSON)

CampoTipoRequeridoDescripción
id_cita_servicio number Sí Código de la cita de servicio donde se guardará la imagen. Corresponde a cita_servicio.id_cita_servicio.
data string Sí Imagen en formato data URL (data:image/jpeg;base64,/9j/4AAQ...) o base64 puro sin prefijo. Se acepta cualquier subformato de imagen.
mimeType string Sí Tipo MIME de la imagen, ej. image/jpeg, image/png, image/webp. Debe estar dentro de los tipos permitidos por el servicio.

Ejemplo de body

{
  "id_cita_servicio": 123,
  "data": "data:image/jpeg;base64,/9j/4AAQSkZJRgABAQAAAQABAAD...",
  "mimeType": "image/jpeg"
}
El campo data puede incluir o no el prefijo data:image/...;base64,. El API lo detecta automáticamente y normaliza antes de calcular el tamaño.

Errores

400Falta id_cita_servicio, falta data o el tipo de archivo no está permitido.
404No existe una cita_servicio con el id indicado.
413Imagen demasiado grande — el tamaño decodificado supera 5 MB.
405Método no permitido — se usó GET, PUT u otro en lugar de POST.

5. Ejemplo: JavaScript / Fetch API

Flujo completo desde la selección del archivo hasta guardar la imagen en una cita de servicio existente:

/**
 * Guarda un File como base64 en cita_servicio.foto_pedido_base64.
 * @param {number} idCitaServicio  Código de cita_servicio
 * @param {File} file  Archivo seleccionado por el usuario
 * @returns {Promise<{ok: boolean, id_cita_servicio: number, tamanio_kb: number}>}
 */
async function guardarImagenCitaServicio(idCitaServicio, file) {
  // 1. Validar en cliente antes de enviar
  if (!file.type.startsWith('image/')) {
    throw new Error('Solo se permiten imágenes');
  }
  if (file.size > 5 * 1024 * 1024) {
    throw new Error('La imagen no puede superar 5 MB');
  }

  // 2. Leer como data URL
  const dataUrl = await new Promise((resolve, reject) => {
    const reader = new FileReader();
    reader.onload  = e => resolve(e.target.result);
    reader.onerror = () => reject(new Error('Error al leer el archivo'));
    reader.readAsDataURL(file);
  });

  // 3. Llamar al webservice
  const resp = await fetch('/api/imagen-base64', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      id_cita_servicio: idCitaServicio,
      data: dataUrl,
      mimeType: file.type,
    }),
  });

  const json = await resp.json();

  if (!resp.ok) {
    throw new Error(json.error || 'Error al procesar la imagen');
  }

  // 4. La imagen ya quedó guardada en la base de datos
  return json;
}

// ── Uso ──────────────────────────────────────────────────────
const input = document.querySelector('input[type="file"]');

input.addEventListener('change', async (e) => {
  const file = e.target.files[0];
  if (!file) return;

  try {
    const idCitaServicio = 123;
    const { tamanio_kb } = await guardarImagenCitaServicio(idCitaServicio, file);
    console.log(`Imagen guardada (${tamanio_kb} KB)`);
  } catch (err) {
    console.error(err.message);
  }
});

6. Ejemplo: Input de archivo en HTML (sin framework)

<!-- Formulario mínimo -->
<input type="file" id="fotoInput" accept="image/*" />
<img id="preview" alt="Vista previa" style="max-width:300px; display:none;" />

<script>
  document.getElementById('fotoInput').addEventListener('change', async (e) => {
    const file = e.target.files[0];
    if (!file) return;

    const reader = new FileReader();
    reader.onload = async (ev) => {
      const resp = await fetch('/api/imagen-base64', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          id_cita_servicio: 123,
          data:     ev.target.result,
          mimeType: file.type,
        }),
      });
      const json = await resp.json();
      if (resp.ok) {
        document.getElementById('preview').src         = ev.target.result;
        document.getElementById('preview').style.display = 'block';
        document.getElementById('info').textContent     =
          `Imagen guardada. Tamaño: ${json.tamanio_kb} KB`;
      } else {
        alert(json.error);
      }
    };
    reader.readAsDataURL(file);
  });
</script>

7. Integración con el Chatbot

El chatbot puede solicitar al usuario una fotografía (resultado de laboratorio, pedido médico, receta) y procesarla con este mismo endpoint antes de enviarla al modelo de IA. 

// En ChatBotViewSupabase.tsx o chatbotService.ts
export async function procesarImagenChatbot(
  file: File
): Promise<{ base64: string; tamanio_kb: number }> {
  const reader = new FileReader();

  const dataUrl = await new Promise<string>((resolve, reject) => {
    reader.onload  = e => resolve(e.target!.result as string);
    reader.onerror = () => reject(new Error('Error al leer imagen'));
    reader.readAsDataURL(file);
  });

  const resp = await fetch('/api/imagen-base64', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ data: dataUrl, mimeType: file.type }),
  });

  if (!resp.ok) {
    const { error } = await resp.json();
    throw new Error(error);
  }

  return resp.json();
}

9. Notas de implementación

AspectoDetalle
Límite de tamaño 5 MB decodificado. El base64 en tránsito es ~33 % más grande (~6.7 MB).
Tipos aceptados Cualquier image/*: JPEG, PNG, WEBP, GIF, BMP, TIFF, etc.
Almacenamiento en BD La columna foto_pedido_base64 en cita_servicio es TEXT. No se incluye en el SELECT general — se carga on-demand con getFotoPedido(id).
CORS El endpoint devuelve Access-Control-Allow-Origin: *, útil si el chatbot o cliente externo necesita llamarlo directamente.
Idempotencia El endpoint es puro (stateless): misma entrada → misma salida. Se puede llamar múltiples veces sin efectos secundarios.
Archivo del API api/imagen-base64.ts (Vercel serverless function). Rewrite configurado en vercel.json.
